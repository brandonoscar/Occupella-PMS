# Contributing to Occupella PMS

Thanks for helping. Occupella PMS keeps the books for property management companies that hold
other people's money in trust, so it is strict about tests, data and licenses. This page is the
short version; [CLAUDE.md](CLAUDE.md) holds every rule in full, and [docs/CI.md](docs/CI.md)
explains each check a pull request runs.

## Ways to help

- **Try it and tell us what broke.** Run the demo (README, "Try the demo") and open an issue
  with the steps that show it. Bug reports with steps get fixed first.
- **Ask for what's missing.** Open a feature request saying what you do today and what the PMS
  should do instead. State rules (a deposit deadline, a notice period) need the statute's
  citation.
- **Fix something.** Issues labeled `good first issue` are a place to start. For anything bigger,
  open an issue first so the approach can be agreed before you write it.
- **Report a security problem privately**, never in an issue: [SECURITY.md](SECURITY.md).

## The rules a pull request is held to

1. **Tests come with the code.** Every change to code adds the tests that cover it; money or
   ledger logic gets a property test too (`tests/properties/`); a new API endpoint gets tests
   for success, a caller who isn't allowed, and bad input.
2. **Synthetic data only**, everywhere: tests, fixtures, screenshots, logs. No real person,
   company, address, bank or tax number. `python -m tools.check_synthetic_data` checks it.
3. **No weakened checks.** Never skip a test, lower a threshold or loosen a check to get green.
   Something that can't pass yet gets an issue, linked from `ci/registry.toml` or a strict xfail.
4. **Licenses.** Every dependency's license must be on the allowlist in `ci/licenses.toml`:
   permissive ones, never GPL, AGPL or a source-available license.
5. **Migrations** are plain SQL files run by dbmate, never edited once committed, and committed
   with `db/schema.sql` regenerated by `scripts/dump_schema.sh`.

## Running the checks

You need Python 3.11, a throwaway Postgres 16 with trust auth, dbmate 2.36.0 and Node 22. Then:

```sh
python3.11 -m venv .venv && . .venv/bin/activate && pip install -r requirements-dev.txt
export DATABASE_URL="postgres://postgres@localhost:5432/pms?sslmode=disable"
scripts/check.sh
```

`scripts/check.sh` runs every check a pull request runs that can run on your machine, and lists
the rest as NOT RUN. CLAUDE.md, "Run the checks", has each one on its own.

## Pull requests

- Work on a branch and open a pull request against `main`; fill in its template, including what
  you ran and what it showed.
- Every required check must be green before it merges.
- By sending a pull request you agree that your contribution is licensed under the Apache License
  2.0, the license of this repository ([LICENSE](LICENSE)).
